# v1.2 Draft Schema Snippets

> Additive changes only. All new fields are optional. Existing v1.1 artifacts validate without modification.

## Cross-Cutting: Version & Standard Compatibility

Every schema needs two changes to accept both v1.1 and v1.2 artifacts:

```jsonc
// BEFORE (v1.1)
"version": { "type": "string", "pattern": "^1\\.1\\.[0-9]+$" }
"standard": { "type": "string", "const": "Service Design Persona Standard v1.1" }

// AFTER (v1.2) — accepts both 1.1.x and 1.2.x
"version": { "type": "string", "pattern": "^1\\.[12]\\.[0-9]+$" }
"standard": { "type": "string", "enum": [
  "Service Design Persona Standard v1.1",
  "Service Design Persona Standard v1.2"
]}
```

Apply this pattern to all 4 schemas (persona, role-card, pairing, journey) and the pattern schema, substituting the appropriate standard name.

```json
"provenance": {
  "type": "object",
  "description": "AI provenance and generation metadata. Supports EU AI Act transparency requirements (Aug 2026).",
  "properties": {
    "generation_method": {
      "type": "string",
      "enum": ["human_created", "ai_assisted", "ai_generated", "mixed"],
      "description": "How this artifact was created. human_created: entirely by humans. ai_assisted: human-led with AI support. ai_generated: primarily AI-generated. mixed: multiple methods across sections."
    },
    "ai_tools_used": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "tool": { "type": "string", "maxLength": 100, "description": "Name of the AI tool (e.g., 'Claude', 'GPT-4')" },
          "version": { "type": "string", "maxLength": 50, "description": "Version or model identifier" },
          "usage": { "type": "string", "maxLength": 200, "description": "What the tool was used for (e.g., 'initial draft generation', 'barrier analysis')" }
        },
        "required": ["tool"],
        "additionalProperties": false
      },
      "description": "AI tools used in creating this artifact"
    },
    "human_reviewed": {
      "type": "boolean",
      "description": "Whether a human has reviewed the AI-generated content"
    },
    "human_reviewed_by": {
      "type": "string",
      "maxLength": 100,
      "description": "Who performed the human review"
    },
    "human_reviewed_date": {
      "type": "string",
      "format": "date",
      "description": "When the human review was completed"
    },
    "data_sources_consent": {
      "type": "boolean",
      "description": "Whether consent was obtained for data sources used in AI generation"
    }
  },
  "additionalProperties": false
}
```

**Integration point:** Add as a sibling to `validation` in each schema's top-level `properties` object. Not added to `required`.

## 3. AI Agent Representation in Journeys

**Applies to:** Journey schema only

### 3a. Journey context — `agents` array

Add to `journey.properties.context.properties`:

```json
"agents": {
  "type": "array",
  "description": "AI agents participating in this journey",
  "items": {
    "type": "object",
    "properties": {
      "id": {
        "type": "string",
        "pattern": "^agent-[a-z0-9_-]+$",
        "maxLength": 60,
        "description": "Unique identifier with agent- prefix"
      },
      "name": {
        "type": "string",
        "maxLength": 100,
        "description": "Human-readable name (e.g., 'Customer Service Bot', 'Order Tracking Agent')"
      },
      "type": {
        "type": "string",
        "enum": ["chatbot", "voice_agent", "recommendation_engine", "workflow_automation", "copilot", "autonomous_agent", "other"],
        "description": "Type of AI agent"
      },
      "capabilities": {
        "type": "array",
        "items": { "type": "string", "maxLength": 100 },
        "description": "What this agent can do (e.g., 'answer product questions', 'process returns')"
      },
      "constraints": {
        "type": "array",
        "items": { "type": "string", "maxLength": 200 },
        "description": "Limitations or boundaries (e.g., 'cannot process refunds over £500', 'must escalate complaints')"
      },
      "autonomy_level": {
        "type": "string",
        "enum": ["advisory", "semi_autonomous", "autonomous"],
        "description": "advisory: suggests but human decides. semi_autonomous: acts within guardrails, escalates edge cases. autonomous: acts independently within scope."
      }
    },
    "required": ["id", "name"],
    "additionalProperties": false
  }
}
```

### 3b. Journey step — `actor` and `handoff`

Add to `journey.properties.phases.items.properties.steps.items.properties`:

```json
"actor": {
  "type": "string",
  "enum": ["human", "ai_agent", "hybrid", "system"],

  "type": "object",
  "description": "Transfer of control between actors at this step",
  "properties": {
    "from": {
      "type": "string",
      "enum": ["human", "ai_agent", "system"],
      "description": "Actor handing off"
    },
    "to": {
      "type": "string",
      "enum": ["human", "ai_agent", "system"],
      "description": "Actor receiving"
    },
    "trigger": {
      "type": "string",
      "maxLength": 200,
      "description": "What triggers the handoff (e.g., 'customer requests human agent', 'confidence below threshold')"
    },
    "fallback": {
      "type": "string",
      "maxLength": 200,
      "description": "What happens if the handoff fails"
    }
  },
  "required": ["from", "to"],
  "additionalProperties": false
}
```

### 3c. Channel — `operated_by`

Add to `journey.properties.phases.items.properties.steps.items.properties.lane_content.properties.channels.items.properties`:

```json
"operated_by": {
  "type": "string",
  "enum": ["human", "ai_agent", "hybrid"],
  "description": "Who operates this channel at this step"
```

```json
"journey_type": {
  "type": "string",
  "enum": ["linear", "adaptive", "orchestrated"],

  "type": "array",
  "description": "External signals that can influence journey flow (for adaptive/orchestrated journeys)",
  "items": {
    "type": "object",

      "id": {
        "type": "string",
        "pattern": "^signal-[a-z0-9_-]+$",
```

## 7. Structured Emotion Model

**Applies to:** Journey schema — emotion lane content

This is a documentation/convention change more than a schema change, because `lane_content` already uses `additionalProperties: true`. The existing emotion values (-2 to +2 integer on `emotional_intensity`) continue to work. The structured model adds optional fields alongside.

Add the following guidance for emotion lane content objects. In a journey step's `lane_content`, when providing emotion data:

```json
"emotions": {
  "type": "array",
  "items": {
    "type": "object",
    "properties": {
      "label": {
        "type": "string",
        "maxLength": 50,
        "description": "Emotion label (e.g., 'frustrated', 'delighted', 'anxious')"
      },
      "intensity": {
        "type": "integer",
        "minimum": -2,
        "maximum": 2,
        "description": "Simple intensity scale — backward compatible with existing v1.1 emotional_intensity"
      },
      "model": {
        "type": "string",
        "enum": ["simple", "dimensional", "categorical"],
        "description": "Emotion model used. simple: existing -2 to +2 scale. dimensional: valence-arousal. categorical: discrete emotion labels."
      },
      "valence": {
        "type": "number",
        "minimum": -1,
        "maximum": 1,
        "description": "Emotional valence from -1 (very negative) to +1 (very positive). For dimensional model."
      },
      "arousal": {
        "type": "number",
        "minimum": 0,
        "maximum": 1,
        "description": "Emotional arousal from 0 (calm) to 1 (highly activated). For dimensional model."
      },
      "category": {
        "type": "string",
        "enum": ["joy", "trust", "fear", "surprise", "sadness", "disgust", "anger", "anticipation"],
        "description": "Plutchik primary emotion category. For categorical model."
      }
    },
    "additionalProperties": false
  },
  "description": "Structured emotion data with optional dimensional/categorical models"
}
```

**Note:** Since `lane_content` uses `additionalProperties: true`, this can be used immediately without schema changes. The snippet above documents the recommended structure for tooling and AI consumers.

## 8. JSON-LD Context

**Applies to:** All 4 schemas + pattern schema (top-level property)

```json
"@context": {
  "type": ["string", "object"],
  "description": "Optional JSON-LD context for semantic interoperability. String form: URL to context document. Object form: inline context mapping."
},
"@type": {
  "type": "string",
  "description": "JSON-LD type identifier (e.g., 'ServiceDesignPersona', 'CustomerJourney')"
}
```

For identity objects, add optional:

```json
"sameAs": {
  "type": "array",
  "items": { "type": "string", "format": "uri" },
  "description": "URIs identifying this same entity in other systems (JSON-LD convention)"
}
```

**Recommended `@context` values:**

| Schema | @type | @context |
|--------|-------|----------|
| Core Persona | `ServiceDesignPersona` | `https://schemas.digitalservice.design/context/v1.2` |
| Role Card | `ServiceDesignRole` | `https://schemas.digitalservice.design/context/v1.2` |
| Pairing | `ServiceDesignPairing` | `https://schemas.digitalservice.design/context/v1.2` |
| Journey | `CustomerJourney` | `https://schemas.digitalservice.design/context/v1.2` |
| Pattern | `ServicePattern` | `https://schemas.digitalservice.design/context/v1.2` |
